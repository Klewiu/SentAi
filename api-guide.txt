================================================================
  SentAi Company Catalog API — Developer Guide
================================================================

Base URL:      http://your-domain.com
Interactive:   /api/schema/swagger-ui/
ReDoc:         /api/schema/redoc/
OpenAPI JSON:  /openapi.json

All public catalog endpoints require NO authentication.
All responses are UTF-8 encoded JSON unless noted otherwise.
Public discovery and feed endpoints expose only companies that are:
  public=true, allow_ai_indexing=true, and human-admin verified.


----------------------------------------------------------------
  AUTHENTICATION (write access only)
----------------------------------------------------------------

The catalog is fully public. Authentication is only needed to
manage company data via the private dashboard API.

  POST /api/auth/login/
  Content-Type: application/json

  { "username": "you@example.com", "password": "yourpassword" }

Response:
  { "token": "abc123...", "user": { ... } }

Use the token in subsequent requests:
  Authorization: Token abc123...


----------------------------------------------------------------
  COMPANY LIST
----------------------------------------------------------------

  GET /api/companies/

Returns a paginated list of all verified public companies (20 per page).

Pagination:
  ?page=2

Filter parameters:
  search        Search company, product, FAQ, keyword, or any supported translation
  city          Filter by city (case-insensitive contains)
  country       Filter by country code, e.g. PL (exact)
  language      Filter by primary language, e.g. en or pl (exact)
  company_type  manufacturing | services | trading | other
  tag           Filter by tag name (case-insensitive contains)
  verified      true — accepted for compatibility; public results are already verified-only
  has_price     true — return only companies with priced products

Ordering (prefix - for descending):
  ?ordering=name
  ?ordering=-updated_at
  ?ordering=-created_at

Example:
  GET /api/companies/?country=PL&company_type=services&ordering=-updated_at

Response shape:
  {
    "count": 42,
    "next": "http://.../?page=2",
    "previous": null,
    "results": [

        "name": "Acme Sp. z o.o.",

----------------------------------------------------------------
  COMPANY DETAIL
----------------------------------------------------------------

  GET /api/companies/{slug}/

Returns the full structured profile for a single company.

Includes caching headers:
  ETag: "d41d8cd98f00b204e9800998ecf8427e"
  Last-Modified: Wed, 06 May 2026 21:42:00 GMT

Use these for conditional GET requests:
  If-None-Match: "d41d8cd98f00b204e9800998ecf8427e"
  If-Modified-Since: Wed, 06 May 2026 21:42:00 GMT


----------------------------------------------------------------
  RECENT UPDATES
----------------------------------------------------------------

  GET /api/companies/updates/
  GET /api/companies/updates/?since=2026-05-01T00:00:00Z

Returns verified public companies whose profiles were updated after the given
datetime. Defaults to the last 7 days when `since` is omitted.

Use this endpoint to keep a local cache fresh without
re-downloading the full catalog on every poll.

The `since` parameter accepts ISO 8601 datetime:
  2026-05-01T00:00:00Z          UTC explicit
  2026-05-01T00:00:00+02:00     with timezone offset
  2026-05-01T00:00:00           naive (treated as UTC)

Response shape:
  {
    "since": "2026-05-01T00:00:00Z",
    "total": 3,
    "results": [ ... ]   <- same shape as /api/companies/ results
  }

Typical polling pattern:
  1. Full sync:    GET /api/public/all.json
  2. Hourly diff:  GET /api/companies/updates/?since=<last_poll_time>


----------------------------------------------------------------
  BULK CATALOG
----------------------------------------------------------------

  GET /api/public/all.json

Returns the full verified public catalog in a single JSON response with metadata.
Use for full syncs or loading the entire catalog into memory.

Response shape:
  {
    "meta": {
      "catalog": "sentai-company-catalog",
      "version": "1.0",
      "generated_at": "2026-05-06T22:00:00+00:00",
      "last_updated": "2026-05-06T21:42:00+00:00",
      "total": 42
    },
    "results": [ ... ]   <- lightweight entries, same as /api/companies/
  }

---

  GET /api/public/catalog.ndjson
  Content-Type: application/x-ndjson

Streams the full verified public catalog as NDJSON (one JSON object per line).
Each line is a complete company profile (same as company.json).
Suitable for large catalogs, streaming pipelines, and LLM ingestion.

Example (curl):
  curl http://your-domain.com/api/public/catalog.ndjson | while IFS= read -r line; do
    echo "$line" | jq .name
  done


----------------------------------------------------------------
  PER-COMPANY STRUCTURED FORMATS
----------------------------------------------------------------

Each company has a URL-safe lowercase slug. Use the slug in all
per-company endpoints.

  GET /api/public/{slug}/company.json
  Content-Type: application/json
  Available: all plans

  Multilingual master profile. It includes stable UUIDs, all published
  translations allowed by the plan, profile URLs, localized feed URLs,
  social profiles, products, and content entries.

  GET /api/public/{slug}/{language_code}/company.json

  A language-specific JSON profile. Only content authored for the requested
  language is returned; untranslated products, tags, and FAQs are omitted.
  Supported language codes: en, pl, de, es, it, fr. A code returns 404 when
  that translation is not published for the company or exceeds its plan limit.
  Localized responses include Content-Language and Link headers containing
  canonical, hreflang alternate, and x-default URLs.

---

  GET /api/public/{slug}/company.jsonld
  GET /api/public/{slug}/{language_code}/company.jsonld
  Content-Type: application/ld+json
  Available: all plans for verified, public, opted-in companies

  Schema.org structured data for the company. Suitable for
  embedding in pages or feeding to knowledge graph tools.

---

  GET /api/public/{slug}/company.md
  GET /api/public/{slug}/{language_code}/company.md
  Content-Type: text/markdown
  Available: all plans for verified, public, opted-in companies

  Human and LLM-readable Markdown profile. Includes name,
  summary, company information, specializations, products,
  content updates and social profiles. The language-specific URL contains
  only customer content authored in that language.

---

  GET /api/public/{slug}/llms.txt
  GET /api/public/{slug}/{language_code}/llms.txt
  Content-Type: text/plain
  Available: all plans for verified, public, opted-in companies

  Plain-text LLM feed following the llmstxt.org convention.
  Contains key facts, links, and structured text suitable for
  direct injection into LLM context windows.


----------------------------------------------------------------
  LLM DISCOVERY
----------------------------------------------------------------

  GET /llms.txt
  Content-Type: text/plain

Site-wide llms.txt listing all verified companies that have opted in
to AI indexing. Each entry links to the multilingual JSON master and every
published language version of the company profile and llms.txt feed.
Follows the https://llmstxt.org convention.

Intended for AI crawlers discovering the catalog automatically.


----------------------------------------------------------------
  PLAN GATING SUMMARY
----------------------------------------------------------------

  Format          BASIC   PLUS    PRO
  --------------- ------- ------- -------
  company.json      YES     YES     YES
  company.jsonld    YES     YES     YES
  company.md        YES     YES     YES
  llms.txt          YES     YES     YES
  site llms.txt     YES     YES     YES *

  * All verified, public, opted-in companies appear in /llms.txt


----------------------------------------------------------------
  SLUGS
----------------------------------------------------------------

Slugs are auto-generated from the company name at creation time.
They are lowercase and URL-safe, e.g.:
  "Acme Sp. z o.o."  ->  "acme-sp-z-o-o"

You can discover all available slugs via:
  GET /api/companies/          (paginated)
  GET /api/public/all.json     (full list, slug field)


----------------------------------------------------------------
  ERROR RESPONSES
----------------------------------------------------------------

  400  Bad Request   — invalid parameter (e.g. bad datetime format)
  404  Not Found     — slug not found, company not verified/public,
                       AI indexing not allowed, or company not verified for publication
  401  Unauthorized  — missing or invalid token (write endpoints only)


----------------------------------------------------------------
  QUICK EXAMPLES
----------------------------------------------------------------

# List Polish service companies, newest first
curl "http://your-domain.com/api/companies/?country=PL&company_type=services&ordering=-updated_at"

# Get full profile for a company
curl "http://your-domain.com/api/companies/acme-sp-z-o-o/"

# Companies updated in the last 7 days (default)
curl "http://your-domain.com/api/companies/updates/"

# Companies updated since a specific date
curl "http://your-domain.com/api/companies/updates/?since=2026-05-01T00:00:00Z"

# Download full catalog as NDJSON
curl "http://your-domain.com/api/public/catalog.ndjson" > catalog.ndjson

# Get Markdown profile for an LLM (any plan)
curl "http://your-domain.com/api/public/acme-sp-z-o-o/company.md"

# Get the Polish-only Markdown profile
curl "http://your-domain.com/api/public/acme-sp-z-o-o/pl/company.md"

# Get LLM feed for a company (any plan)
curl "http://your-domain.com/api/public/acme-sp-z-o-o/llms.txt"

# Site-wide LLM index
curl "http://your-domain.com/llms.txt"

Updates pagination: /api/companies/updates/?since=ISO8601&page=1 returns up to 100 records. Keep the same since value and follow next_page until null. Periodically reconcile the full catalog to detect removals. Catalog detail supports If-None-Match and returns 304 when the current representation is unchanged.
